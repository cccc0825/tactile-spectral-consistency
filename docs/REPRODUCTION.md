# Reproduction workflow

Run from the repository root. Use separate output directories; never overwrite stored reference outputs. Source-selection code must not use target labels or target distribution means.

## 1. Prepare an isolated source-fitting tree

After installing the recorded dependencies and running `python scripts/bootstrap_public.py`:

```sh
python outputs/research_v2/tools/prepare_fresh_run.py prepare \
  --project-root /tmp/tactile-source-run-001
python scripts/bootstrap_public.py --project-root /tmp/tactile-source-run-001
python outputs/research_v2/tools/prepare_fresh_run.py check \
  --project-root /tmp/tactile-source-run-001
```

The preparation helper preserves the original 36-file dependency layout. Its generated runtime record now describes the local environment; the Mendeley compatibility inputs are minimized public citation metadata generated by `bootstrap_public.py`, not original webpage snapshots. No algorithm or frozen simulation input is changed by this packaging adaptation.

`check` verifies prepared hashes and Python syntax and reports missing inputs. It does not establish that data extraction, model selection or evaluation has run.

## 2. Acquire public recordings and run source stages

Use the helper as follows, replacing `STEP` with a listed stage:

```sh
python outputs/research_v2/tools/prepare_fresh_run.py run \
  --project-root /tmp/tactile-source-run-001 --step STEP
```

| Sequence | Stage | Requirements / output |
|---|---|---|
| Cluster | `acquire-cluster` | Network; public ZIP member index; HTTP ranges, approximately 4.6 GB historically |
| | `extract-cluster` | Raw accelerometer ranges; produces PSDs |
| | `extract-fixed-space` | Raw ranges; fixed spatial-resolution PSDs |
| | `select-cluster-svm` | New PSDs; source-only SVM selection |
| | `extract-cluster-cnn` | Raw ranges and label order; spectrogram tensors |
| | `configure-cluster-cnn` | New tensors and original initialization weights |
| | `select-cluster-cnn` | Configuration and training dependencies |
| External | `acquire-external` | Network; generated public metadata; IMU members of Mendeley v1 |
| | `smoke-external` | Dependencies and preprocessing checks |
| | `extract-external` | Raw inputs and unchanged protocol |
| | `external-qc-decision` | Recomputed quality/duplicate checks matching the recorded conditions |
| | `publish-external` | New eligibility decision and blocked staging arrays |
| | `external-handoff` | New hashes, labels and source folds |
| | `configure-external-cnn` | New handoff, Cluster configuration template and weights |
| | `select-external-svm` | New common PSD and QC bindings |
| | `select-external-cnn` | New CNN configuration |

Each stage records its own receipt. The fixed QC criteria produced 49 excluded episodes and one removed duplicate in the recorded study, leaving 3,550 unique eligible episodes (2,354 source and 1,196 target). A changed panel must stop for review rather than inherit the old counts or release. CNN preparation requires the original PyTorch initialization URL and hash given in `THIRD_PARTY.md`; download it into `outputs/research_v2/experiments/cnn/resnet34-b627a593.pth` inside the fresh tree. No pretrained weights are redistributed here.

The original dataset archive may be unavailable or change its HTTP range behavior; a source retrieval failure is not a successful acquisition. A new machine must budget disk space for raw ranges, processed arrays and checkpoints in addition to the source repository.

## 3. Target evaluation

The helper intentionally ends at source selection. Target producers are:

- `outputs/research_v2/experiments/run_calibration.py cluster evaluate`
- `outputs/research_v2/experiments/cnn_baseline.py evaluate`
- `outputs/research_v2/experiments/run_external_calibration.py evaluate`
- `outputs/research_v2/experiments/cnn/run_external_baseline.py evaluate --global-release PATH`

Execute them only in a fresh working tree after the required new input/model checks and source seals. `outputs/research_v2/research/seal_external_models.py` records the study's gate and its required source receipts; old acceptance records must not be reused as evidence that new models passed. Inspect its requirements before execution. The earlier legacy `run_calibration.py external` loader does not implement the final external split: use `run_external_calibration.py`.

This source release does not automate a new independent acceptance decision for full raw-data/CNN training. The commands above are an implementation map, not a claim of an already executed clean-machine end-to-end run.

## 4. Analysis and saved-result replay

After a completed study, `analysis/analyze_revision.py`, `make_artifacts.py`, `make_supplement.py` and `make_calibrator_artifacts.py` produce the tables and plots. Additional scripts analyze alignment and per-specimen effects. Their data dependencies must come from completed runs.

The two original external prediction files needed for the compact specimen replay are bundled with their original result hashes. The overview has its own compact plotting inputs. These two workflows are self-contained once their runtime dependencies are installed; see root README commands.

`tools/portable_reproduce.py` supports `--level tables` and `--level svm` against the complete archived experiment package. That package includes all predictions/manifests and, for SVM inference, PSDs and saved models. Those large archives are not bundled in this source repository. Do not run the portable entrypoint here expecting a full archived replay without obtaining those inputs. It will reject missing or mismatched hashes.

## 5. Evidence levels

- Unit checks validate code invariants, splits and signal operations.
- The synthetic diagnostic runs the actual calibration and source-selection pipeline on explicitly synthetic inputs.
- The paired specimen replay recomputes a descriptive analysis of saved predictions; it does not retrain a classifier or provide a new independent validation sample.
- Figure rendering reconstructs a plot from recorded source data.
- Full raw acquisition and CNN retraining on a new machine require additional data and compute and are not established by the preceding checks.

The public source inventory preserves hashes of original research files and separately identifies the new metadata/bootstrap documentation. Research hypotheses, test exposure chronology, numerical outcomes and protocol freezes remain unchanged.
